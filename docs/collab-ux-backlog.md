# dsh-collab 使用摩擦清单（仍未解决的）

> 只记**当前实现里仍然存在**的摩擦。已随机制删除而消失的条目（租约到期、心跳续租、
> 循环终止自动释放、读者推送、定向唤醒/广播）不再保留。
> 每条都要能被一次检查判定；动手改之前先看这里有没有人已经记过。

## 1. 写门控只在模型工具的参数层生效，shell 完全绕过【实测】

- 判据：`src/spec.ts` 的写工具白名单只含带路径参数的那几个工具，**不含** `bash` / `pwsh`；
  未知工具在 `src/gate.ts` 里一律放行。
- 后果：设置卡片写着「拦截」，但同一路径用 `bash`（`sed -i`、heredoc、`python - <<EOF`）去写，
  门控一次都不触发。README 承认了这条旁路，但**模型侧没有任何运行时提示**。
- 方向：`bash` 命中被占路径时投一条**旁路提示**（不是拒绝），让调用方知道这次没被保护。

## 2. 项目键只由 cwd 决定 ⇒ 跨 worktree 时锁形同不存在【一手 + 实测】

- 判据：项目键 = 会话 cwd（`src/paths.ts`），状态文件名由 cwd 哈希（`src/collab-core.ts`），
  路径只在落在 cwd 下时才剥前缀。
- 一手：子代理在 git worktree（如 `/tmp/xxx-tests`）里改 `tests/`，锁却声明在主仓库的 `tests/`；
  两边落在**两个不同的状态文件**里、互不可见，而物理文件其实是同一份。
- 方向：允许显式指定项目键（按 git 顶层目录派生），或让 worktree 与主仓库共用一份状态。

## 3. 落在 cwd 外的绝对路径被静默相对化【实测】

- 判据：`norm()` 直接去掉开头的 `/`；不匹配 cwd 时原样返回。
- 后果：`/x/y` 被归一成 `x/y`，于是别的项目下的同名相对路径可能撞上你的锁（假阳性拒绝），
  或者本该匹配的声明匹配不上（假阴性放行）。两种情况都**没有任何提示**。
- 方向：把「落在 cwd 外的绝对路径」显式判为不可判定并提示，而不是静默相对化。

## 4. `collab_board` 漏传 `op` 时报错读不出「你漏了 op」【实测】

- 判据：两个工具的 handler 都返回 `未知操作：undefined`。
- 后果：调用方（模型）很难反推是漏了参数还是传错了值。会话记录里有 2 次因此把几百字正文重发了一遍。
- 方向：`op` 缺失时单独给 `missing op (one of: post, read)`，与「传了非法值」区分开。

## 5. `release` 用 `paths` 匹配不到任何声明时仍返回 `ok: true`【实测】

- 判据：`release()` 在 `released: []` 时仍返回 `ok: true`（只带空数组）。
- 后果：调用方无法从 `ok` 判断"我还持有吗"，`ok: true` 制造虚假的完成感。会话记录里出现过一次，
  随后那个会话又手写重试了一遍。
- 方向：`released` 为空时带上 `warning`（或改判 `not-found`），文案里点明「没有任何声明匹配这些路径」。
