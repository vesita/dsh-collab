# 委托与验收（默认工作方式）

> **默认策略，不是可选项。** 除非任务小到一步能做完，否则先跑 §0。

## 0. 判据

**能用一段话把规格写清楚，并用一次检查判定对错？**

- 能 → 委托：后台 + 同一条消息里并行发一批
- 不能 → 先把规格想清楚（这是主 AI 的活），再决定
- 一步能做完的小事 → 自己做
- 无论走哪条 → 验收、下结论、决定提交，留在主 AI

判据问的是**可验收性**，不是难度：难而可验收能派，易而不可验收派了也收不回来。

该委托的信号：准备连读 5 个以上文件只为得一个事实；准备把同一动作重复到第 3 个文件；只想「先跑一遍看看」而结果是一张数字表；要复核自己刚得出的结论。

## 1. 分工

| 任务 | 谁做 |
|---|---|
| 探索、调研、测量、机械改造、独立复核 | 子代理 |
| 方案设计、取舍、拆任务、定接口 | 主 AI |
| 验收、下结论、决定提交、对用户负责 | 主 AI |
| 一步能做完的小事 | 主 AI |

**主 AI 的产出是「规格 + 判定」，不是「最忙的人」。**

## 2. 动作序列

1. **定界**：切成互不重叠的单元，按**文件集**切（任意两个单元不改同一批文件）。
2. **写规格**：每个单元一份自包含 prompt（§3）。
3. **并行发**：互不依赖的单元放在同一条消息里，默认后台。串行只用于真依赖。
4. **改派**：发现规格错了，立刻 send_message 让在跑的那个转向，别等它跑完。
5. **收口**：等待期间做**不依赖它们**的事；结果到齐再统一下结论。
6. **验收**：§5。不做这步，前五步作废。

一步做不完、又切不出互不重叠单元的任务，先派一个「探索」单元把边界摸清，再拆。

## 3. 规格 prompt

子代理看不到本对话，六项缺一不可：

| 项 | 内容 | 缺了会怎样 |
|---|---|---|
| 目标 | 产出什么 | 它自己猜范围 |
| 背景 | 已实测结论 + 证据出处，注明「不要重新论证」 | 重推一遍，可能推反 |
| 步骤 | 编号动作 | 顺序与边界靠猜 |
| 硬约束 | 不许改什么、不许提交、只能在哪写 | 顺手改了别处 |
| 验收口径 | 哪些断言必须成立 | 收不回可判定的结果 |
| 输出格式 | 贴什么、不贴什么（§4） | 报告灌满主会话 |
| 置信度 | 区分实测与推测 | 不知道哪句能信 |

### 最值钱的两样

有它们时子代理常常一次做对；只有散文规格时它会跑偏：

1. **一个可照抄的先例**：「照 `path/to/reference.ts` 的形状做」远胜描述形状。
2. **精确的接口契约**：把签名、类型、返回值原文贴进 prompt，别让它猜 API。

### 模板

```
# 目标
<产出什么>

# 背景（已实测，不要重新论证）
<结论 + 证据出处：文件:行 / 命令>

# 你要做的
1. ...
2. ...

# 硬约束
- 只读，不修改任何文件        ← 探索类写死
- 不要 git commit
- 只在 /tmp 下写临时文件

# 验收口径
<哪些断言必须成立>

# 输出格式
<§4 的贴 / 不贴清单>

# 置信度
区分实测与推测；标注证据强度（单次 / 配对 / 多组）
```

对照：✗「看看这个仓库有什么问题」→ 没口径，收回一段无法判定的散文。
✓「读 `src/*.ts`，找出把时间戳渲染成相对倒计时的位置，输出 `文件:行` 与该字符串；不改任何文件；找不到就明说」→ 可逐行核对。

## 4. 报告体积：贴什么、不贴什么

「要求贴原始证据」和「别灌满主会话」是同一件事的两面：无约束地要求贴原文，会让**报告本身成为主会话最大的一块**。

**贴**：关键命令的**输出尾部**；失败的断言原文；`git diff --stat`；数字表与文件清单；实测产物的**那一行**字符串。

**不贴**：完整日志（给 `/tmp` 路径 + 尾部）；完整源码（给路径 + 行号）；已通过的断言逐条罗列；报告自己的过程叙述。

需要全文时给路径，不给内容。

## 5. 验收（永远留在主 AI）

- **亲手跑一次关键命令**：测试、构建、复现。不拿摘要下结论。
- **`git diff` 逐条看**，重点看**删除**和没预料到的文件。
- **专门读注释**：子代理会把**没验证的断言**和**过期数字**留在代码注释里；注释里的数字回到源头核。
- **改动的既有断言逐条比对**：把**文案/标签改动**与**判定条件改动**分开看。被弱化的测试比失败的测试更危险——它看起来是绿的。
- **最强的那条证据必须落进仓库**：只在 `/tmp` 或一次性命令里出现过的验证，既不可复现也不受回归保护。要求它落成仓库里的测试文件，或明确说明为何不能。
- **追问两句**：「有没有改断言？」「有没有绕开检查？」
- **记录它没做的部分**：子代理倾向于只报做完的。
- 区分**「没测出问题」**与**「没有问题」**。

验收不通过 → 带失败证据派回**同一个**子代理，不要自己接手改一半。
两个单元的产出互相矛盾 → 统一口径后只重派其中一个。
它顺手改了不该改的文件 → `git diff` 定位回退，禁止项写进下次的硬约束。

## 6. 独立性与成本

**独立性**：同模型 + 同提示的「独立复核」会犯同类错。要真独立就换**输入通道**：读源码而不是读结论，自己跑命令而不是复算你给的数字。最终结论仍需主 AI 的一手证据。

**成本**：省的是主会话上下文；贵的是每个子代理**从零重建上下文**。所以拆得太细更贵（十个小单元 = 付十次固定开销），一次并行优于多次串行。

**粒度基准：一个子代理 = 一个能用一段话描述完的完整问题。**

§4 的体积约束与这里的粒度是同一件事：收益只在报告有界时才成立。

## 7. 工具与执行

| 工具 | 用在 |
|---|---|
| `subagent` | 任务自包含，不需要本对话上下文 |
| `subagent_fork` | 任务建立在**已完成的本对话**上：审阅、续写、复核 |
| `workflow` | 大规模扇出：同一动作套用到几十个文件，或多阶段流水线 |
| `ralph` | 仅当人类明确要求「新鲜代理迭代」时 |

默认后台发起，然后去做**不依赖它**的事；不空等、不轮询。有明确终点时用 `job_output(wait=true)` 正常等到结束。已经派出去的活，自己不要再做一遍。

## 8. 与协作锁

多个子代理或会话并行改同一仓库时：`collab_lock op=claim` 声明目录，开工前 `op=overview`，只读调研用 `mode=read`，完成 `op=release`，长任务 `op=heartbeat` 续租。写冲突的代价高于规划时多切一刀。

## 9. 踩坑对照

| 坑 | 改法 |
|---|---|
| 把验收也委托出去 | 验收留在主 AI |
| 没写验收口径 | 先写「怎么算对」，再写「做什么」 |
| 让子代理自己定范围 | 写死范围与不许碰的东西 |
| 两个子代理改同一批文件 | 按文件集切分，或先 claim |
| 让它去查你已经知道的事 | 已知事实写进背景，注明「不要重新论证」 |
| 只看摘要就下结论 | §5 |
| 要求「贴全部原始证据」 | §4：贴尾部、贴失败断言、贴路径 |
| 只信「全部通过」 | 追问改断言 / 绕检查，并亲手跑一次 |
| 拆成十个微型任务 | 合并到一个完整问题 |
| 没依赖也串行发 | 同一条消息并行发起 |
| 派完自己又做一遍 | 派完转做不依赖它的部分 |
| 验收失败后自己上手改 | 附失败证据，重派给同一个子代理 |
