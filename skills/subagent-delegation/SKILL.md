# 委托与验收（默认工作方式）

> **默认策略，不是可选项。** 除非任务小到一步能做完，否则先跑 §1。

## 1. 判据

**能用一段话把规格写清楚，并用一次检查判定对错？**

- 能 → 委托；互不依赖的单元放在同一条消息里并行发
- 不能 → 先把规格想清楚（这是主 AI 的活），再决定
- 一步能做完的小事 → 自己做
- 无论走哪条 → 验收、下结论、决定提交，留在主 AI

判据问的是**可验收性**，不是难度：难而可验收能派，易而不可验收派了也收不回来。

该委托的信号：准备连读一批文件只为得一个事实；准备把同一动作重复到第 3 个文件；只想「先跑一遍看看」而结果是一张数字表；要的是**只读取证或审计**；要复核自己刚得出的结论。**探索阶段怎么派，见 §1.1**（这是最容易被跳过的一格：任务还没成形时，人最想「我自己先看看」）。

| 任务 | 谁做 |
|---|---|
| 探索、调研、测量、机械改造、独立复核、只读审计 | 子代理 |
| 方案设计、取舍、拆任务、定接口 | 主 AI |
| 验收、下结论、决定提交、对用户负责 | 主 AI |
| 一步能做完的小事 | 主 AI |

**主 AI 的产出是「规格 + 判定」，不是「最忙的人」。连探索也派出去**——自己一个个翻文件凑事实，是主会话最容易漏出去的一大块。

### 1.1 探索阶段：默认先派，别自己翻（最常漏的一条）

**「先摸清情况」不是主 AI 的活。** 主会话里最贵的一段上下文，就是为回答一个问题而连读的十几个文件、连跑的十几条命令；而这些事实**只有一次用处**（写进规格或结论），用完就永远占着上下文。

触发以下任一条，就把**整个问题**包给一个子代理，而不是自己开读：

| 触发场景（探索期最常见的五种） | 派什么 | 收回什么 |
|---|---|---|
| 要为「根因在哪 / 改哪几行」连读 ≥3 个文件 | 只读定位单元 | `文件:行` 清单 + 一行根因 |
| 要确认「仓库里是否已有先例、约定、旧结论」 | 只读盘点单元 | 命中的 `文件:行` 与原文；没有就让它明说 |
| 要跑一遍才知道输出长什么样（探针、度量、对比） | 探针单元 | 原始输出尾部 + 退出码 |
| 要写一个**会失败**的测试把契约钉死 | 测试单元（独立 worktree） | RED 输出 + 断言片段 |
| 刚得出一个结论，想再确认一次 | 独立复核单元（换输入通道：让它读源码，不是读你的结论） | 一致 / 不一致 + 依据 |

**判据一句话**：这个事实会写进**你的规格或结论**，而不是写进**你要交付的代码** —— 那就该由子代理去取。

只有三种探索可以自己做：一条命令能答的事实；你已经知道、只差复核的常量；必须由你拍板的取舍（拆分、接口、优先级、范围）。

**派完不要再做一遍。** 等待期间只做**不依赖它**的活（写下一波规格、改文档、接线、验收已回来的产出）。反过来，让子代理去查一件你**已经知道**的事，等于付两次钱——写「背景」时注明「不要重新论证」，就是为了堵这个。

## 2. 动作序列

1. **定界**：切成互不重叠的单元，按**文件集**切（任意两个单元不改同一批文件）。
2. **写规格**：每个单元一份自包含 prompt（§3）。
3. **并行发**：互不依赖的单元放在同一条消息里，默认后台。串行只用于真依赖。
4. **改派**：发现规格错了，立刻 send_message 让在跑的那个转向，别等它跑完。
5. **收口**：等待期间做**不依赖它们**的事；结果到齐再统一下结论。
6. **验收**：§5。不做这步，前五步作废。

一步做不完、又切不出互不重叠单元的任务，先派一个「探索」单元把边界摸清，再拆。

**并发会互相踩编译产物。** 若多个单元要在同一仓库里构建或跑测试，给每个单元**独立的 git worktree**（在里面软链 `node_modules`）。否则并发的 `tsc`／测试套件会造出与改动无关的**假失败**，你分不清哪条是真的。

## 3. 规格 prompt

子代理看不到本对话，八项缺一不可：

| 项 | 内容 | 缺了会怎样 |
|---|---|---|
| 目标 | 产出什么 | 它自己猜范围 |
| 背景 | 已实测结论 + 证据出处，注明「不要重新论证」 | 重推一遍，可能推反 |
| 步骤 | 编号动作 | 顺序与边界靠猜 |
| 硬约束 | 不许改什么、不许提交、只能在哪写 | 顺手改了别处 |
| 停止边界 | 做完哪几项就停（§3.1） | 交付后自行扩大范围 |
| 验收口径 | 哪些断言必须成立 | 收不回可判定的结果 |
| 输出格式 | 贴什么、不贴什么（§4） | 报告灌满主会话 |
| 置信度 | 区分实测与推测 | 不知道哪句能信 |

### 3.1 停止边界（最容易被漏写的一条）

子代理交付完之后，**会自己给自己加活**：产出一份没人要的清单、拿旧结论去动仓库、再派一层子代理、跑去留言板发公告。在它看来这是"顺手帮忙"，在你看来全是**未授权写入**。

写死一句就够：

```
# 停止边界
做完 <这几项> 就停。不要顺手改别的文件、不要新增测试、不要改文档、
不要提交、不要创建新的子代理。
```

**验收前先查越界**：`git status`／`git diff --stat` 是不是只有你点名的文件、有没有你没让它建的文件、它派的子代理有没有真的跑起来。越界产出**直接回退**，不要"既然做了就看看"——那会把没验证过的东西混进你的结论。

### 3.2 最值钱的三样

1. **一个可照抄的先例**：「照 `path/to/reference.ts` 的形状做」远胜描述形状。
2. **精确的接口契约**：把签名、类型、返回值原文贴进 prompt，别让它猜 API。
3. **一个会失败的检查**（负向对照）：让子代理把被检查的东西**故意弄坏一次**，贴出失败输出，再修回来。只会说「全部通过」的检查，你分不清它是真通过还是根本没跑到——**静默跳过的测试看起来和通过一模一样**（§5）。

### 3.3 模板

```
# 目标
<产出什么>

# 背景（已实测，不要重新论证）
<结论 + 证据出处：文件:行 / 命令>

# 你要做的
1. ...
2. ...

# 硬约束
- 只读，不修改任何文件        ← 探索类写死
- 不要 git commit
- 临时文件只写 <路径>          ← 唯一的例外是要落进仓库的测试文件（§5）
- 只能改 <点名的文件>          ← 其余文件一律不碰

# 停止边界
做完 <这几项> 就停；不要 <列出不许顺手做的事>。

# 验收口径
<哪些断言必须成立；要求负向对照>

# 输出格式
<§4 的贴 / 不贴清单>

# 置信度
区分实测与推测；标注证据强度（单次 / 配对 / 多组）
```

对照：

- ✗「看看这个仓库有什么问题」→ 没口径，收回一段无法判定的散文。
- ✓「读 `src/*.ts`，找出把时间戳渲染成相对倒计时的位置，输出 `文件:行` 与该字符串；不改任何文件；找不到就明说」→ 可逐行核对。
- ✗「顺手把发现的技术债也整理一下」→ 未授权范围，回来一堆没验收过的改动。
- ✓「只交这份清单就停，不要动手修」→ 真要它修时，再派一轮。

### 3.4 第一行就是它的名字（零成本的协作可读性）

**子代理在协作锁里的显示名来自它的会话标题，而标题来自你写的那条 prompt 的开头。** 所以：

```
【A1 测试脚手架】        ← 第一行只放短标签，空一行，再写正文
```

- 这样它在别人的占用列表、访问通知、门控文案里就是 `【A1 测试脚手架】…`，一眼可辨；
- 不写标签，你收到的就是 `你是一个子代理，在**主检出**` 这种**提示词残段**——实测 17 个显示名里 11 个长这样，等于没有名字；
- **预算**：标题约被截到 40 字节（CJK ≈ 13 字，ASCII ≈ 24 字），所以标签要短、带括号，截断时才看得出边界；
- 与 `note` 分工：`note` 说明这条**声明**在干什么，标签说明**这个代理**是谁，两者都写。

这是**父 AI 完全可控**的一格：不依赖插件、也不依赖 DSH 的实现细节。

## 4. 报告体积：贴什么、不贴什么

「要求贴原始证据」和「别灌满主会话」是同一件事的两面：无约束地要求贴原文，会让**报告本身成为主会话最大的一块**。

**贴**：关键命令的**输出尾部**与退出码；失败的断言原文；负向对照的前后输出；`git diff --stat`；数字表与文件清单；实测产物的**那一行**字符串。

**不贴**：完整日志（给 `/tmp` 路径 + 尾部）；完整源码（给路径 + 行号）；已通过的断言逐条罗列；报告自己的过程叙述。

需要全文时给路径，不给内容。

## 5. 验收（永远留在主 AI）

- **亲手跑一次关键命令**：测试、构建、复现。不拿摘要下结论。
- **`git diff` 逐条看**：重点看**删除**、没预料到的文件、以及**被弱化的断言**。
- **专门读注释**：子代理会把**没验证的断言**和**过期数字**留在代码注释里；注释里的数字回到源头核。
- **静默跳过不算通过**：出现 `SKIP`、`skipped`、或提前 `return` 就当作**未验证**。让跳过**默认失败**，只有显式打开的开关才允许放行，且要打醒目横幅。**被弱化的测试比失败的测试更危险——它看起来是绿的。**
- **盯住空 catch**：`catch {}` 把真实故障变成「看起来正常」。一次静默失败的推送，因为空 catch 让整轮排查无从下手。要求区分「合法忽略（有注释说明理由）」与「应当留痕」，并把后者改到可观测。
- **改动的既有断言逐条比对**：把**文案／标签改动**与**判定条件改动**分开看。
- **最强的那条证据必须落进仓库**：只在 `/tmp` 或一次性命令里出现过的验证，既不可复现也不受回归保护。要求它落成仓库里的测试文件，或明确说明为何不能。
- **追问两句**：「有没有改断言？」「有没有绕开检查？」
- **记录它没做的部分**：子代理倾向于只报做完的。
- 区分**「没测出问题」**与**「没有问题」**。

验收不通过 → 带失败证据派回**同一个**子代理，不要自己接手改一半。
两个单元的产出互相矛盾 → 统一口径后只重派其中一个。
它顺手改了不该改的文件 → `git diff` 定位回退，越界项写进下次的硬约束。

## 6. 独立性与成本

**独立性**：同模型 + 同提示的「独立复核」会犯同类错。要真独立就换**输入通道**：读源码而不是读结论，自己跑命令而不是复算你给的数字。最终结论仍需主 AI 的一手证据。

**成本：这里真正的目标不是省钱，是让主 AI 用得起最强的模型。**
主会话上下文是全场最贵的资源 —— 主 AI 通常跑最强也最贵的模型，它每一轮的上下文都按最强的价码重读一遍。
所以主 AI 要**低上下文运行**：只留结论、决策、验收证据，把探索 / 测量 / 机械改造放到便宜的子代理上。
代价算清楚，这条才是可执行的：省的是主会话上下文；贵的是每个子代理**从零重建上下文** ⇒
拆得太细更贵（十个小单元 = 付十次固定开销），一次并行优于多次串行；
"把整个问题包给一个子代理、只收文件:行 + 结论"是最省主上下文的一手形态。

**粒度基准：一个子代理 = 一个能用一段话描述完的完整问题。**

## 7. 工具与并发

| 工具 | 用在 |
|---|---|
| **`subagent`** | **首选、默认就用它**。任务自包含、不需要本对话上下文：探索/调研/测量/机械改造/独立复核/只读审计；同一动作重复到第 3 个文件以上的批量改造。它看不到本对话 ⇒ 规格与背景**照 §3 写进 prompt**（这本来就是本技能要求的写法）。**严禁**让子代理执行 `cordis_inspect_query` 的 `platform:'client'` 查询（§10 硬禁令） |
| `subagent_fork` | **不推荐**：fork 会把父会话整段转录继承给子代理，子代理容易误认为自己是主 AI（实测：自派后代、回头找父会话要裁决）。需要"接着本对话做"时，把必要背景摘进 prompt，再派一个 `subagent` |
| `workflow` | 大规模扇出（几十个文件 / 多阶段流水线）——**仅当用户明确要求 workflow 或大规模多 agent 编排**；一两个委托用普通 subagent 更省 |
| `ralph` | **仅当人类明确要求**「新鲜代理迭代」时 |

> **前台编排会被打断**：`workflow` / `ralph` 是**前台**工具，运行期间父会话收到新消息会中断整轮 ⇒ 编排半途被 `cancelled`。需要长跑编排时优先用后台委派，或把编排拆小、一次只跑一件。

默认后台发起，然后去做**不依赖它**的事；不空等、不轮询。有明确终点时用 `job_output(wait=true)` 正常等到结束〔长跑看护另见全局约定〕。已经派出去的活，自己不要再做一遍。

**多个单元并行改同一仓库**：按**文件集**切分；要在同一仓库构建就各给一个 worktree；再叠加 `collab_lock op=claim` 声明目录——开工前先 `op=overview`，只读调研用 `mode=read`，完成 `op=release`，长任务 `op=heartbeat` 续租。路径冲突又谈不拢时用 `collab_board` 留言协商。写冲突的代价高于规划时多切一刀。

**子代理被强杀会留下僵尸声明**：会话被 kill / dsh 重启时来不及 `release`，它未到期的声明会一直占着路径（租约最长 24h），只有持有者本人能 `release`。别手工改状态文件——先用 `collab_lock op=reap` 看候选（默认 dry-run、绝不改状态），确认后再 `op=reap confirm=true` 显式回收；它只收「未过期 + holder 不在 `agents.list()` + 不是自己 + age 超 600s」的声明，绝不自动触发。

## 8. 目标轮次与自动唤醒（别空烧轮次）

长任务用 goal 工具跨轮推进时，**每一轮都是一次完整的模型步**：它消耗上下文，还可能挤掉正在跑的并行工作。所以一轮**必须换到真进度**。

- **不要把「等子代理」当成一轮工作。** 如果这一轮唯一能做的是把 `list_agents`／测试／构建**再跑一遍**，那不是进度——上一轮已经验过了。空转轮的正确处理是：
  - 还有**不依赖在跑单元**的活 → 做那件活（写文档、起草提交信息、验收已经回来的产出、把下一波规格写好）；
  - 确实没有 → **直接说明「当前无未阻塞工作，在等哪些单元」并结束这一轮**，不要用重复验证或轮询去凑。
- **轮次上限按「真实波次」估，不按挂钟时间估。** 一个四波的任务设几十轮上限，等于给自己安排了几十轮空转。宁可设小、做完再往上调。
- **一波发齐。** 同一批互不依赖的单元必须在**一条消息**里发完；分多轮发 = 多轮「等」，而每轮都在付费。
- **规划时就把「不依赖任何人的活」列成清单**（文档、版本号、提交信息、CLI 帮助文本、已回来产出的验收），轮次空转时从里面取，而不是现找。
- **报告异步到达，收到即结**：当轮就把验收做完，不要留到下一轮再"顺便看看"。
- **区分「等」与「堵」**：等的是有终点的后台单元（正常）；堵的是缺规格、缺授权、缺信息（该问人，不该空转）。

## 9. 踩坑速查

| 坑 | 改法 |
|---|---|
| 把验收也委托出去 | 验收留在主 AI |
| 没写验收口径 | 先写「怎么算对」，再写「做什么」 |
| **没写停止边界** | 它交付后自行扩大范围；§3.1 写死一句 |
| 让它去查你已经知道的事 | 已知事实写进背景，注明「不要重新论证」 |
| 两个子代理改同一批文件 | 按文件集切分，或先 claim |
| 多单元在同一仓库并发构建 | 各给一个隔离 worktree，否则收回假失败 |
| 只信「全部通过」 | 要求负向对照，证明检查真的会失败 |
| 把 SKIP 当成通过 | 静默跳过一律按未验证处理 |
| **用重复验证／轮询凑一轮** | §8：没有未阻塞工作就说清楚并结束，别空烧 |
| **轮次上限按时间估** | 按真实波次估；设大了就是几十轮空转 |
| 拆成十个微型任务 | 合并到一个完整问题 |
| 没依赖也串行发 | 同一条消息并行发起 |
| 派完自己又做一遍 | 派完转做不依赖它的部分 |
| 验收失败后自己上手改 | 附失败证据，重派给同一个子代理 |
| **让子代理查客户端 Inspect** | §10：子代理无浏览器页面必永久挂起；主 AI 在主会话预查，结果写进背景 |
| **只信子代理的收尾消息** | §11.3：空收尾会被记成 `completed`；开文件验产物 |
| 两个子代理在同一仓库跑构建 | §11.2：只许一个 `npm run build`，其余 `--noEmit` |
| 按目录级声明锁 | §11.2：按文件声明；目录级互斥会挡死无关工作 |

## 10. 硬禁令：子代理禁止调用 client 平台 Inspect（Slots/Theme 等）

**严禁子代理调用 `cordis_inspect_query` 的 `platform:'client'` 查询。**

### 10.1 机制与故障事实（实测，不要重新论证）

- **故障实测**：子代理会话 `769c2e33` 调 `cordis_inspect_query{platform:'client',provider:'Slots',method:'listSubTree'}`，21:34:00.300Z 发出，直到 21:39:45.117Z 被主 AI 中断才以 `Error: Slots.listSubTree: Client inspect query Slots.listSubTree was cancelled` 收尾 —— 空挂 **344.8 秒**；同一进程内主会话做**同一个调用**瞬时返回（正控）。
- **根因机制**：`@deepseek-ai/dsh-cordis-host-runner/lib/types/inspect-registry.js` 的 `queryClient`（:107-147）只被「拥有该 `agentId` 的浏览器页面」的应答 settle，`resolveClientQuery`（:87-106）里 `pending.request.agentId !== agent.id` 直接 `{accepted:false}`；子代理会话没有浏览器页面 ⇒ 永不 settle。工具文档亦明确声明 "remains pending until a page answers or the Tool is cancelled"。

### 10.2 危险信号清单

委派提示词（prompt）中一旦出现以下需求或词汇，即为踩坑的典型形态：
- 出现 `Slots`、`Theme`、`listSubTree`、`listTokens`
- 包含「看看界面里有什么槽位」「查一下当前前端主题变量」「检视客户端渲染结构」等指令
- 让子代理自行通过 `cordis_inspect_list` 遍历并调用客户端 Provider

### 10.3 反例与正例

- ✗ **反例（让子代理自查）**：
  ```markdown
  # 目标
  调用 cordis_inspect_query 查看 Slots 树，找出设置页有哪些槽位，然后写出客户端卡片。
  ```
  *后果*：子代理在第一步即永久挂起，直到父会话超时或手动 `interrupt_agent`，白白耗尽等待时间。

- ✓ **正例（主会话预查 + 结果入背景）**：
  主 AI 在主会话中执行 `cordis_inspect_query{platform:'client',provider:'Slots',method:'listSubTree'}` 瞬时拿到结果，提取出目标槽位契约后写入子代理规格：
  ```markdown
  # 目标
  编写 client 卡片组件代码。
  
  # 背景（主 AI 已预查，不要重新检视）
  目标槽位为 settings.plugin.item，其 standardProps 包含 useResource、useSessions；无 close 回调。
  ```

## 11. 主 AI 工作流：分批并行 + 文件级互斥 + 验收不外包

本节每一步都在真实的多插件维护里跑过（同一仓库四路并发、零撞车）。

### 11.1 六步

1. **定方案**：把目标拆成**互不重叠路径**的工作线，先写一张表：目标 / 归属路径 / 谁做 / **验收判据**。判据要能「一次检查判定对错」，否则先想清楚规格（§1）。
2. **主 AI 预查**：需要界面契约、既有实现、版本事实的，**先在主会话查好**，写成提示词里的「背景（已实测，不要重新论证）」。别让子代理去查你已经知道的事 —— §10 就是这条被违反后的极端后果。
3. **同一条消息并行发起两到四路**，每路一个完整问题，各自 `collab_lock op=claim`。
4. **文件级互斥**：同一仓库并发时按**文件**声明锁，并在每份提示词里点名「你不能碰这几个文件 —— 另一个人在改」。这是防撞车最有效的一句。
5. **验收留在主 AI**：自己复跑测试、读 diff、查越界写入，并且**打开文件确认产物真的存在**（§11.3）。
6. **集成留主 AI**：版本号 / 打包 / 安装 / 重启 / 实机探针。**重启前确认所有子代理都已停止** —— 重启会杀整条 cgroup，跑着的子代理会被连带杀掉。

### 11.2 同一仓库并发的三条硬规则（实测）

- 按**文件**声明锁，不按目录：目录级互斥会把无关工作挡死。
- **只许一个子代理跑 `npm run build`**（它先 `rm -rf lib`）；其余一律 `tsc --noEmit`，或把产物输出到临时目录。
- 构建与测试**不是**可并行步骤：需要同一份产物目录的两路，必须一路跑完再跑另一路。

### 11.3 子代理会静默失败：三种形态与兜底

| 形态 | 现场特征 | 兜底 |
|---|---|---|
| **永久挂起** | 工具调用只发出、永不返回结果 | §10 硬禁令；插件层 `tools/pre-execute` 直接拒绝 |
| **空收尾** | 最终助手消息 `content: []`、`outputTokens: 0`，而 turn 仍记成 `completed` | 要求「绝不允许空报告」；**主 AI 开文件验产物**；重派 |
| **传输中断** | `turn/end` 原因是 `error`，消息 `terminated`、代码 `UNKNOWN` | 重派；同一提示词往往第二次就过 |

实测样本（同一路由 `google-antigravity/gemini-3.8-flash`，是实测不是推断）：短提示词探针一次成功；中等有界任务（新建文件 + 测试）成功；**长提示词 + 重活三连败** —— 两次空收尾（`35e92799` 序号 190、`b748c446` 序号 41，均 `outputTokens: 0` 且 turn 记成 `completed`）、一次 `terminated`（`cace4b76`，正在流式推理时断掉，一个文件都没写）。这三种情况下 `model-retry` **一次都没介入**，turn 照常收尾。**归因倾向模型/传输层，不是提示词写法**；但三路都**零产物**，所以：

- 收尾消息**不能**当交付证据；产物必须由主 AI 亲眼确认（列目录 + 开文件 + 复跑测试）。
- 压缩提示词、把「先落盘、再修补」钉在最前面，能提高存活率（本次短提示词重派即成功）。
- 反复失败的**重活**（例如新写一个几百行的界面文件）不要死磕委派：主 AI 自己写更快。

### 11.4 什么时候**不要**派

- 写规格需要「本会话的记忆」——例如把这一轮的踩坑写成纪律：写规格的成本已经等于干活。
- 任务的核心是判断与取舍，而不是探索、机械改造或独立复核。
- 已经连续两轮零产物的重活：换人不如换手。
