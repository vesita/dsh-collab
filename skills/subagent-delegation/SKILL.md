# 委托与验收（默认工作方式）

## 1. 判据

能用一段话写清规格、且能用一次检查判定对错？问**可验收性**不是难度：能 → 委托，不依赖的**同一条消息**并行发；不能 → 先想清规格。验收、结论、提交永远留主 AI。

### 1.1 探索阶段默认先派，别自己翻（最常漏）

为答一个问题自己连读文件/跑命令，是主会话最贵的上下文，事实只用一次。触发任一条就把**整个问题**包给只读子代理（收回 `文件:行`+结论）：找根因连读 ≥3 文件；查先例/约定；跑探针；写会失败的测试钉契约；复核结论（**读源码不读结论**）。

**事实写进你的规格或结论、而非交付代码 → 派出去**；自己做只剩一条命令能答的、已知只差复核的常量、必须你拍板的取舍。**派完不要再做一遍。**

## 2. 动作序列

按**文件集**切互不重叠单元（两单元不改同一批文件）→ 每单元写自包含规格（§3）→ 不依赖的**同一条消息**并行发、默认后台 → 规格错了立刻 `send_message` 让在跑的转向 → 等待期做不依赖它们的事 → 到齐统一下结论并验收（§5）。切不出先派探索单元摸边界。同仓库多单元构建各给**独立 git worktree**（软链 `node_modules`），否则并发的 `tsc`/测试会造出**假失败**。

有一个例外值得单独记：**子代理中途断掉**（回合以 `error` / 空收尾结束）时，先别把它当"派失败"——**先唤醒它接着做**（§10.4），只有在它已经不可唤起、或唤醒一两次仍无产出时才重派。

## 3. 规格 prompt

八项缺一不可，照抄：

```
# 目标：<产出什么>
# 背景（已实测，不要重新论证）：<结论 + 证据出处 文件:行/命令>
# 步骤：1. ...
# 硬约束：只读不改文件 / 不 git commit / 临时文件只写 <路径> / 只能改 <点名的文件>
# 停止边界：做完 <这几项> 就停；不要 <不许顺手做的事>
# 验收口径：<哪些断言必须成立；要求负向对照>
# 输出格式：<§4 的贴/不贴清单>
# 置信度：区分实测与推测；标注证据强度
```

**停止边界**最易漏：子代理交付后会自己加活（编清单、动仓库、再派子代理）＝**未授权写入**；**验收前查越界**（`git status`/`git diff --stat` 是否只有点名文件），越界回退。

**最值钱的三样**：① 可照抄的先例（照 `path/to/reference.ts` 做）；② 接口契约原文（签名/类型/返回值贴进 prompt）；③ 会失败的检查（负向对照：故意弄坏、贴失败、再修回）。

**第一行就是名字**：协作锁显示名＝会话标题＝prompt 开头；第一行只放短标签（`【A1 测试脚手架】`）再空行写正文（约截 40 字节，CJK ≈ 13 字）；`note` 说明**声明**，标签说明**代理是谁**。

## 4. 报告体积

**贴**：命令输出**尾部**与退出码、失败断言原文、负向对照前后输出、`git diff --stat`、数字表/文件清单。**不贴**：完整日志/源码（给路径）、已通过断言逐条、过程叙述。

## 5. 验收（永远留在主 AI）

- **亲手跑一次关键命令**（测试/构建/复现），不拿摘要下结论。
- **`git diff` 逐条看**：重点看**删除**、意外文件、**被弱化的断言**；**开文件确认产物存在**。
- **静默跳过按未验证**（`SKIP`/`skipped`/提前 `return`/空 `catch {}`，跳过**默认失败**）；**证据落进仓库**；**读注释**（注释里的数字回源头核）。

验收不通过 → 带证据派回**同一个**子代理；越界改动 → `git diff` 回退并写进下次硬约束。

## 6. 独立性与成本

同模型+同提示的复核会犯同类错；要真独立就换**输入通道**（读源码不读结论、自己跑命令）。结论仍需主 AI 一手证据。

**成本**：目标是让主 AI 用得起最强模型——主会话上下文最贵，要**低上下文运行**（只留结论/决策/验收证据），探索/测量/机械改造放便宜子代理；子代理**从零重建上下文** ⇒ 拆太细更贵。**粒度：一个子代理 = 一个能用一段话描述完的完整问题。**

## 7. 工具与并发

- **`subagent`（首选、默认）**：任务自包含、不需本对话上下文；规格与背景照 §3 写进 prompt。**严禁**让它跑 client 平台 Inspect（§10.1）。
- `subagent_fork` **不推荐**（继承整段转录、易误认为主 AI）；`workflow` 仅**用户明确要求**大规模扇出时用；`ralph` **仅当人类明确要求**。

> `workflow`/`ralph` 是**前台**工具：运行期间父会话收到新消息会中断整轮（`cancelled`）；长跑编排优先后台委派或拆小。

默认后台发起，做**不依赖它**的事，不空等、不轮询；有明确终点用 `job_output(wait=true)` 等到结束；派出去的活自己不再做一遍。

**多单元并行改同一仓库**：按**文件集**切（§10.2），构建各给 worktree；用 `collab_lock`（claim/release/heartbeat，只读 `mode=read`，僵尸声明 `op=reap`）声明占用，冲突走 `collab_board`。

## 8. 目标轮次（别空烧轮次）

用 goal 跨轮推进时**每轮都是一次完整模型步**，必须换到真进度。

- **只等子代理不算一轮**：若这轮唯一能做的是把 `list_agents`/测试/构建**再跑一遍**，那不是进度；改做不依赖在跑单元的活（写文档、起草提交信息、验收已回产出、写下一波规格），没有就**说明「无未阻塞工作，在等哪些单元」结束本轮**。
- **上限按「真实波次」估**（宁设小）；**一波发齐**（同批不依赖单元在**一条消息**发完）；**报告收到即验**；**区分「等」与「堵」**（堵缺规格/授权/信息该问人）。

## 9. 踩坑速查

| 坑 | 改法 |
|---|---|
| **让子代理查客户端 Inspect** | §10.1 永久挂起；主 AI 预查后写进背景 |
| **只信收尾消息（静默空收尾）** | §10.3 会记成 `completed`；开文件验产物 |
| **子代理意外终止（error/空收尾）就重派** | §10.4：先 `list_agents` 看它还在不在，在就 `send_message` 唤醒接着做（它保留上下文） |
| **往 `collab_board` @ 一个已经停下的子代理等它动** | §10.4：`agent.inject` **不唤醒 driver**；要它动只能 `send_message` |
| **同仓库多个 `npm run build`** | 只许一个；其余 `tsc --noEmit`（§10.2） |
| 用重复验证凑一轮 / 上限按时间估 | §8 |

## 10. 硬禁令与并发

### 10.1 子代理禁止调 client 平台 Inspect（永久挂起）

**严禁**子代理调 `cordis_inspect_query{platform:'client'}`（`Slots`/`Theme` 等）：它无浏览器页面，**永不 settle**（实测空挂 344.8 秒；主会话瞬时返回）。危险信号：prompt 出现上述词、「看看界面有什么槽位」「查主题变量」「检视客户端渲染结构」；正确做法是**主 AI 预查**后写进规格「背景」。

### 10.2 同仓库并发的硬规则

- 按**文件**声明 `collab_lock`（不按目录）；prompt 点名「你不能碰这几个文件」。
- **只许一个子代理跑 `npm run build`**；其余 `tsc --noEmit`；构建与测试**不可并行**。

### 10.3 静默失败的三种形态与兜底

| 形态 | 现场特征 | 兜底 |
|---|---|---|
| **永久挂起** | 只发出、永不返回 | §10.1；`tools/pre-execute` 拒绝 |
| **空收尾** | `content: []`、`outputTokens: 0`，turn 仍记 `completed` | 要求「绝不允许空报告」；**开文件验产物**；**先按 §10.4 唤醒它继续**，不行再重派 |
| **传输中断** | `turn/end` 为 `error`、`terminated`、`UNKNOWN` | **先按 §10.4 唤醒它继续**（它保留着上下文）；两次不行再重派 |

收尾消息**不能**当交付证据；反复失败的重活主 AI 自己写更快。

### 10.4 子代理意外终止：**先唤醒它接着做**，别急着重派

**怎么判定它意外终止了**：`turn/end` 是 `error` / `terminated` / `UNKNOWN`；或收尾是空的
（`content: []`、`outputTokens: 0`）却记成 `completed`；或久等之后 `list_agents` 里它已不再是
`running`。

**为什么先唤醒**：被唤醒的是**同一个会话**，它保留着整段上下文和已经做完的那部分工作；
重派则是从零重建上下文（更贵），而且很可能撞上同一处坑。判据是"它还在不在"，不是"它失败过"：

1. `list_agents` 看它还在不在 —— `idle` 和 `ready` 都**还能被唤起**（`ready` = 只在存储里、
   可续，**不是终结**）；只有它整个消失，才直接谈重派。
2. 对它 `send_message`（只对**直接子代理**有效；名字随部署可能不同 —— 就是那个能给**已在跑或已停下**的子代理发消息的工具）。内容要三件事：**说明你看到它中断了**、
   **要它先自报进度**、**给出继续点与验收口径**。例：

   > 你上一个回合以 `error` 结束，没有交出报告。请：① 先用三五句话说明你已经改了哪些文件、
   > 哪些还没动；② 接着做完剩下的 X；③ 收尾贴命令输出的尾部与退出码，不要只给摘要。

3. **顺手提醒它重新 `collab_lock op=claim`**：它的循环一停，之前持有的声明会在宽限期后被
   **自动释放**，而它**不会知道**自己已经丢锁（没人唤醒它时就收不到那条告知）。不提醒它，
   它就会在"以为自己还占着"的状态下继续写。

**三条边界**：

- **唤醒有代价**，被唤醒的回合是一次完整模型步 ⇒ **最多试 1–2 次**；两次都还是空收尾/再中断，
  就换人重派或自己写（§10.3 末句）。
- **只能唤醒 depth-1**：孙子代理由它的父代理去唤醒，你这边只能 `interrupt`。
- **留言板/`agent.inject` 唤醒不了任何人**：那条通道的契约是 `send(msg, next-step, wakeup=false)`
  —— 只把消息挂进收件箱、**不唤醒 driver**。想让它动起来只有 `send_message` 这一条路；
  往 `collab_board` 里 @ 一个已经停下的子代理是白费。
- **别把唤醒当重派用**：不要重发一遍同样的规格 —— 那等于重派却更贵。它保留着上下文，
  所以指令是"接着做 + 先自报进度"。

### 10.5 什么时候**不要**派

写规格需要「本会话的记忆」（如把本轮踩坑写成纪律）；核心是判断取舍；连续两轮零产物的重活。
