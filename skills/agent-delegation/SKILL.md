# 委托与验收（默认工作方式）

**默认先派子智能体。** 主会话亲手做的每一件事都要有理由 —— 「这活太小」「我自己顺手做一下」都不是理由，
而是**漏派**：碎片活累积起来才是主会话最贵的开销（上下文最贵，见 §6）。不依赖的单元在**同一条消息**里并行发。
**有官方智能体团队工具就用团队派**（下一段），没有才降到 §7 的一次性工具。

## 1. 判据：默认先派，自己动手要理由

**默认路径 = 官方智能体团队**：用 `spawn_teammate` 派生成员，用 `team_task_*` 开共享任务板
（`team_task_create` / `team_task_get` / `team_task_update` / `team_task_list`，任务上写清 owner 与
write scope），用 `send_message` / `list_agents` / `wait_agent` 协作。一个成员 = 一次 `spawn_teammate`，
它的 prompt 就是 §3 的自包含规格；多步协作就给它在任务板上开任务、按依赖串起来。
这条路的**代价是换不了成员模型**（§6.1），换来的东西值这个价：有身份、有共享任务板、能被转向与唤醒。
部署里没有 `spawn_teammate` / `team_task_*` 时才降级到 §7 的 `subagent` / `subagent_fork`（一次性、无任务板）。

三问，按顺序过：

1. **能用一段话写清规格吗？** 不能 → 先想清规格，或这条留给自己拍板。
2. **做完能用一次检查判定对错吗？** 能 → **派出去**。判据是**可验收性，不是难度**：
   越机械、越琐碎、一眼就会的活越该派（它只消耗子智能体的上下文，不消耗你的）。
3. **派完自己还剩什么？** 结论、决策、验收证据 —— 这三样才是主会话该留的。

只有三类活值得自己动手：**必须本会话拍板的取舍**、**一条命令就能答完的**、**已经只差复核的常量**。
其余一律先派；**验收、结论、提交永远留主 AI，派出去的活自己不再做一遍。**

### 1.1 探索阶段默认先派，别自己翻（最常漏）

为答一个问题自己连读文件/跑命令，是主会话最贵的上下文，事实只用一次。触发任一条就把**整个问题**包给只读子智能体（收回 `文件:行`+结论）：找根因连读 ≥3 文件；查先例/约定；跑探针；写会失败的测试钉契约；复核结论（**读源码不读结论**）。

**事实写进你的规格或结论、而非交付代码 → 派出去**；自己做只剩一条命令能答的、已知只差复核的常量、必须你拍板的取舍。**派完不要再做一遍。**

## 2. 动作序列

按**文件集**切互不重叠单元（两单元不改同一批文件）→ 每单元写自包含规格（§3）→ 不依赖的**同一条消息**并行发、默认后台 → 规格错了立刻 `send_message` 让在跑的转向 → 等待期做不依赖它们的事 → 到齐统一下结论并验收（§5）。切不出先派探索单元摸边界。同仓库多单元构建各给**独立 git worktree**（软链 `node_modules`），否则并发的 `tsc`/测试会造出**假失败**。
走官方团队时，「并行发」就是在一条消息里建多个成员、各自在任务板上认领自己的任务（§8 的一波发齐）。

有一个例外值得单独记：**子智能体中途断掉**（回合以 `error` / 空收尾结束）时，先别把它当"派失败"——**先唤醒它接着做**（§10.4），只有在它已经不可唤起、或唤醒一两次仍无产出时才重派。

## 3. 规格 prompt

八项缺一不可，照抄：

```
# 目标：<产出什么>
# 背景（已实测，不要重新论证）：<结论 + 证据出处 文件:行/命令>
# 步骤：1. ...
# 硬约束：只读不改文件 / 不 git commit / 临时文件只写 <路径> / 只能改 <点名的文件>
# 停止边界：做完 <这几项> 就停；不要 <不许顺手做的事>
# 验收口径：<哪些断言必须成立；要求负向对照>
# 输出格式：<§4 的贴/不贴清单>
# 置信度：区分实测与推测；标注证据强度
```

官方团队里这份规格同时是 `spawn_teammate` 的 prompt 与 `team_task_create` 的 description —— 两处别写岔。

**停止边界**最易漏：子智能体交付后会自己加活（编清单、动仓库、再派子智能体）＝**未授权写入**；**验收前查越界**（`git status`/`git diff --stat` 是否只有点名文件），越界回退。

**最值钱的三样**：① 可照抄的先例（照 `path/to/reference.ts` 做）；② 接口契约原文（签名/类型/返回值贴进 prompt）；③ 会失败的检查（负向对照：故意弄坏、贴失败、再修回）。

**第一行就是名字**：协作锁显示名＝会话标题＝prompt 开头；第一行只放短标签（`【A1 测试脚手架】`）再空行写正文（约截 40 字节，CJK ≈ 13 字）；`note` 说明**声明**，标签说明**代理是谁**。

## 4. 报告体积

**贴**：命令输出**尾部**与退出码、失败断言原文、负向对照前后输出、`git diff --stat`、数字表/文件清单。**不贴**：完整日志/源码（给路径）、已通过断言逐条、过程叙述。

## 5. 验收（永远留在主 AI）

- **亲手跑一次关键命令**（测试/构建/复现），不拿摘要下结论。
- **`git diff` 逐条看**：重点看**删除**、意外文件、**被弱化的断言**；**开文件确认产物存在**。
- **静默跳过按未验证**（`SKIP`/`skipped`/提前 `return`/空 `catch {}`，跳过**默认失败**）；**证据落进仓库**；**读注释**（注释里的数字回源头核）。

验收不通过 → 带证据派回**同一个**子智能体；越界改动 → `git diff` 回退并写进下次硬约束。

## 6. 独立性与成本

同模型+同提示的复核会犯同类错；要真独立就换**输入通道**（读源码不读结论、自己跑命令）。结论仍需主 AI 一手证据。

**成本**：目标是让主 AI 用得起最强模型——主会话上下文最贵，要**低上下文运行**（只留结论/决策/验收证据），探索/测量/机械改造放便宜子智能体；子智能体**从零重建上下文** ⇒ 拆太细更贵。**粒度：一个子智能体 = 一个能用一段话描述完的完整问题。**

### 6.1 子智能体的模型：官团队成员换不了，降级路径才挑得动

**代价先说**：官方成员工具 `spawn_teammate` 只收 name/description/prompt/context，**没有** `provider` / `model` 参数 —— 走官方团队就**换不了成员模型**，成员继承你正在用的路由。要指名模型只有两条路：

- **`subagent` / `subagent_fork`（受 Host 开关管辖）**：不写 `provider`/`model` 就**继承你正在用的那一个**（`configured?.provider ?? parentOptions.provider`，`dsh-tool-subagent/lib/index.js:69`）。Host 设置 `subagent-model-selection-settings` 的 `enabled` 为真且 `allowedModels` 非空时，这两个工具会多出 `provider` / `model` / `reasoning_effort` 三个参数，并注册 `list_subagent_models` 列出**允许的路由**。两参数必须成对给；路由不在允许列表内会被**拒绝**（`child LLM route "…" is not allowed for this Session`）—— 先 `list_subagent_models` 查、再填，**不要编路由**。
- **`workflow` 的 `agent(prompt, opts)`（与开关无关）**：`opts.provider` / `opts.model` 一直是每个子智能体的独立覆盖，`meta.phases[]` 也能按阶段声明。

**怎么选，两条建议不打架**：要**独立性**（复核、对抗性验证，尤其是换掉同模型先验）→ 走降级路径指名另一个家族的模型，代价是失去任务板与身份；要**长期协作**（多步、要共享任务板、要能被转向/唤醒）→ 走官方团队，代价是换不了成员模型。走团队时就把「换模型」这条**放掉**，别写成假装做到了。

**负向对照**：如果某次委派换了模型，报告里应当看得出差别（不同的结论、不同的失败模式）；每次都"换了模型"却永远同结论，等于没换 —— 先核实路由真的被工具接受了（参数被拒会直接报错，不会静默回落）。

## 7. 工具与并发

**先看你自己的工具目录**：派生 / 转向 / 等待的语义随部署而变，本技能不复述它们。**默认按官方智能体团队办**：

- **有 `spawn_teammate` / `team_task_*`（官方 Agent Teams）→ 默认路径**：`spawn_teammate` 派生成员、`team_task_*` 开共享任务（写清 owner 与 write scope）、`send_message` 转向或唤醒、`list_agents` 看状态、`wait_agent` 等待 —— 这些**官方 `team:policy` 段已逐条写明**（含「inactive 只表示没有回合在执行」「`wait_agent` 不唤醒，先 `list_agents` 再 `send_message`」），照它做；本技能只补它不管的：规格（§3）、验收（§5）、并发（§10.2）。成员的**模型换不了**（§6.1）。
- **降级：部署里没有团队工具时**，用上游的一次性工具 `subagent`（首选）或 `subagent_fork`（不推荐：继承整段转录、易误认为主 AI）。它们**没有共享任务板、没有身份、不能被转向**，所以任务必须完全自包含（规格与背景照 §3 写进 prompt）；换来的是能指名 `provider` / `model`（§6.1）。**严禁**让它跑 client 平台 Inspect（§10.1）。
- `workflow` 仅**用户明确要求**大规模扇出时用；`ralph` **仅当人类明确要求**。

> `workflow`/`ralph` 是**前台**工具：它们占着当前这一轮，返回前父会话做不了别的。期间收到的新消息只是按 `steer`（最近的 step 边界领走）/ `followup`（下一轮）排进 inbox，**不会**中断这一轮 —— 要中断得显式停，此时 `turn/end` 的 `reason.kind` 才是 `aborted`。长跑编排仍优先后台委派或拆小。

默认后台发起，做**不依赖它**的事，不空等、不轮询；有明确终点用 `job_output(wait=true)` 等到结束；派出去的活自己不再做一遍。

**多单元并行改同一仓库**：按**文件集**切（§10.2），构建各给 worktree；用 `collab_lock`（claim/release，只读 `mode=read`，确证死亡的声明 `op=reap`）声明占用，冲突走 `collab_board`。官方团队的任务板管树内 DAG，`collab_lock` 管树间的路径占用，两者并存。

## 8. 目标轮次（别空烧轮次）

用 goal 跨轮推进时**每轮都是一次完整模型步**，必须换到真进度。

- **只等子智能体不算一轮**：若这轮唯一能做的是把 `list_agents`/测试/构建**再跑一遍**，那不是进度；改做不依赖在跑单元的活（写文档、起草提交信息、验收已回产出、写下一波规格），没有就**说明「无未阻塞工作，在等哪些单元」结束本轮**。
- **上限按「真实波次」估**（宁设小）；**一波发齐**（同批不依赖单元在**一条消息**发完）；**报告收到即验**；**区分「等」与「堵」**（堵缺规格/授权/信息该问人）。

## 9. 踩坑速查

| 坑 | 改法 |
|---|---|
| **让子智能体查客户端 Inspect** | §10.1 永久挂起；主 AI 预查后写进背景 |
| **只信收尾消息（静默空收尾）** | §10.3 会记成 `completed`；开文件验产物 |
| **子智能体意外终止（error/空收尾）就重派** | §10.4：先看它还在不在（官方成员用 `list_agents`），在就发消息唤醒接着做（它保留上下文） |

## 10. 硬禁令与并发

### 10.1 子智能体禁止调 client 平台 Inspect（永久挂起）

**严禁**子智能体调 `cordis_inspect_query{platform:'client'}`（`Slots`/`Theme` 等）：它没有浏览器页面来应答。两种失败形态，**都是白费**：

- **rc.2 之前**：**永不 settle** —— 实测空挂 344.8 秒直到被主 AI 中断（同样的调用主会话瞬时返回）。
- **rc.2 起**：上游 `dsh-cordis-host-runner` 补了「无活页面即在派发前失败」与 `clientInspectTimeoutMs`（默认 `10000` 毫秒）超时，现象从「永久挂起」变成「十秒后报错」。纪律不变：换来的仍然是一个界面事实都拿不到。

危险信号：prompt 出现上述词、「看看界面有什么槽位」「查主题变量」「检视客户端渲染结构」；正确做法是**主 AI 预查**后写进规格「背景」。

### 10.2 同仓库并发的硬规则

- 按**文件**声明 `collab_lock`（不按目录）；prompt 点名「你不能碰这几个文件」。
- **只许一个子智能体跑 `npm run build`**；其余 `tsc --noEmit`；构建与测试**不可并行**。
- 官方团队里把这条写进成员的 prompt 与任务的 write scope，别只靠它自觉。

### 10.3 静默失败的三种形态与兜底

| 形态 | 现场特征 | 兜底 |
|---|---|---|
| **永久挂起** | 只发出、永不返回 | §10.1；`tools/pre-execute` 拒绝 |
| **空收尾** | `content: []`、`outputTokens: 0`，turn 仍记 `completed` | 要求「绝不允许空报告」；**开文件验产物**；**先按 §10.4 唤醒它继续**，不行再重派 |
| **传输中断** | `turn/end` 的 `reason.kind` 为 `error` / `aborted` / `blocked` / `max-tokens` / `interrupted`（`completed` 之外的收尾） | **先按 §10.4 唤醒它继续**（它保留着上下文）；两次不行再重派 |

收尾消息**不能**当交付证据；反复失败的重活主 AI 自己写更快。

### 10.4 子智能体/成员意外终止：**先看它还在不在**，别急着重派

**怎么判定它意外终止了**：`turn/end` 的 `reason.kind` 不是 `completed`（实际取值只有 completed / aborted / blocked / error / max-tokens / interrupted / forked）；或收尾是空的
（`content: []`、`outputTokens: 0`）却记成 `completed`；或久等之后它已不再处于运行态。

**为什么先唤醒**：被唤醒的是**同一个会话**，它保留着整段上下文和已经做完的那部分工作；
重派则是从零重建上下文（更贵），而且很可能撞上同一处坑。判据是"它还在不在"，不是"它失败过"：

1. **先看它在不在**：官方成员看 `list_agents` —— `inactive` 只表示**当前没有回合在执行**，
   还能被 `send_message` 唤起；legacy 子智能体的 `idle` / `ready` 同样还能被唤起
   （`ready` = 只在存储里、可续，**不是终结**）。只有它整个消失，才直接谈重派。
2. **对它发一条消息**（官方成员 `send_message` 按 `target` 名字；legacy 子智能体用那个能给
   **已在跑或已停下**的子智能体发消息的工具）。内容要三件事：**说明你看到它中断了**、
   **要它先自报进度**、**给出继续点与验收口径**。例：

   > 你上一个回合以 `error` 结束，没有交出报告。请：① 先用三五句话说明你已经改了哪些文件、
   > 哪些还没动；② 接着做完剩下的 X；③ 收尾贴命令输出的尾部与退出码，不要只给摘要。

3. **顺手提醒它重新 `collab_lock op=claim`**：会话句柄结束时它持有的声明会被**自动释放**，
   而它**不会知道**自己已经丢锁（没人唤醒它时就收不到那条告知）。不提醒它，
   它就会在"以为自己还占着"的状态下继续写。

**三条边界**：

- **唤醒有代价**，被唤醒的回合是一次完整模型步 ⇒ **最多试 1–2 次**；两次都还是空收尾/再中断，
  就换人重派或自己写（§10.3 末句）。
- **只能唤醒直接下属**：更下一层的成员由它的父级去唤醒；官方团队是扁平 roster（只有 Lead 建直属
  teammate，无嵌套），不存在更深一层。
- **留言板/`agent.inject` 唤醒不了任何人**：那条通道的契约是 `send(msg, next-step, wakeup=false)`
  —— 只把消息挂进收件箱、**不唤醒 driver**；往 `collab_board` 里 @ 一个已经停下的子智能体是白费。
- **别把唤醒当重派用**：不要重发一遍同样的规格 —— 那等于重派却更贵。它保留着上下文，
  所以指令是"接着做 + 先自报进度"。

### 10.5 什么时候**不要**派

写规格需要「本会话的记忆」（如把本轮踩坑写成纪律）；核心是判断取舍；连续两轮零产物的重活。
